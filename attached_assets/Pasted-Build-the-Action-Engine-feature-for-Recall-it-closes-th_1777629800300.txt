Build the Action Engine feature for Recall — it closes the gap between saving content and actually doing something with it.
STEP 1 — Supabase tables:
sql-- Store extracted action items from saved articles
CREATE TABLE action_items (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  article_id UUID REFERENCES saved_articles(id) ON DELETE CASCADE,
  action TEXT NOT NULL,
  intent_type TEXT DEFAULT 'general',
  status TEXT DEFAULT 'pending',
  priority INT DEFAULT 3,
  due_date DATE,
  completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
ALTER TABLE action_items ENABLE ROW LEVEL SECURITY;
CREATE POLICY 'Users manage own actions' ON action_items
  FOR ALL USING (auth.uid() = user_id);

-- Store weekly action plans
CREATE TABLE action_plans (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  week_start DATE NOT NULL,
  plan_json JSONB NOT NULL,
  generated_at TIMESTAMPTZ DEFAULT NOW(),
  user_goals TEXT
);
ALTER TABLE action_plans ENABLE ROW LEVEL SECURITY;
CREATE POLICY 'Users manage own plans' ON action_plans
  FOR ALL USING (auth.uid() = user_id);

-- Store user goals
ALTER TABLE saved_articles ADD COLUMN IF NOT EXISTS intent_type TEXT DEFAULT 'general';
ALTER TABLE saved_articles ADD COLUMN IF NOT EXISTS action_items_extracted BOOLEAN DEFAULT FALSE;
STEP 2 — Auto-extract actions when article is saved:
In the existing POST /api/summarize endpoint, after generating the summary, add a background call to Claude Haiku:
Prompt: 'Analyze this article and extract concrete actionable items. Article: [title + bullets]. Return JSON only: { intent_type: one of [tool/roadmap/strategy/tutorial/resource/inspiration], actions: [array of max 5 specific action strings starting with a verb like Install, Read, Try, Build, Set up, Apply, Review] }. If the article has no clear actions, return { intent_type: resource, actions: [] }'
Store the intent_type on the saved_articles row. Insert each action into the action_items table with status pending, linked to the article_id.
STEP 3 — New route POST /api/action-plan/generate:
Accepts optional { goals } string.
Fetches all pending action_items for the user from the last 30 days with their linked article titles.
Fetches user's stated goals from their profile.
Sends to Claude Haiku:
'You are helping an indie founder turn their saved content into a real action plan. Their goals: [goals]. Their pending actions from saved content: [list of action items with source article]. Generate a focused weekly action plan. Return JSON: { week_theme: one sentence theme for the week, daily_actions: { monday: [2 actions], tuesday: [2 actions], wednesday: [2 actions], thursday: [2 actions], friday: [2 actions] }, quick_wins: [3 actions completable in under 10 minutes], tools_to_try: [tools saved but never acted on, max 3], insight: one honest observation about what they save vs what they actually need to do }'
Save the plan to action_plans table. Return the plan.
STEP 4 — New route GET /api/action-plan/current:
Returns the most recent action_plan for the current week. If none exists for this week, auto-generates one.
STEP 5 — New route PATCH /api/action-items/:id:
Updates action status to completed or snoozed. Sets completed_at timestamp.
STEP 6 — New route GET /api/action-items/pending:
Returns all pending action items grouped by intent_type, ordered by created_at.
